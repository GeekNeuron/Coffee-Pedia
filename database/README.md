# Coffee Pedia — نسخه‌ی مرجع داده

این پوشه نسخه‌ی JSON دو مجموعه‌ی اصلی محتوای اپ را نگه می‌دارد. اپ در زمان اجرا این فایل‌ها را **نمی‌خواند**؛ آن‌ها برای بازبینی، مقایسه، ترجمه و انتقال بعدی به یک بک‌اند یا سیستم مدیریت محتوا در دسترس‌اند. منبع اجرایی داده پوشه‌ی `js/database/` است.

## فایل‌ها

| فایل | محتوا |
|---|---|
| `encyclopedia.json` | ۱۷ دسته و ۲۰۶ مدخل دانشنامه (تاریخ، گیاه‌شناسی، برشته‌کاری، شیمی، تکنیک، تجهیزات، افزودنی‌ها، همراهی با غذا، ارزیابی حسی، سلامت، اقتصاد، فرهنگ، هنر، فولکلور، واژگان، ایمنی، آینده و نوآوری) |
| `recipes.json` | ۱۲ گروه و ۱۱۴ نوشیدنی |

واژه‌نامه، رویدادها، تجهیزات، آزمایشگاه، کارگاه، دست به آچار و جدول‌های ابزارها فقط در `js/database/` هستند و نسخه‌ی JSON ندارند.

## چرا دو نسخه؟

- `database/*.json` فرمت ساده و قابل‌مقایسه و قابل‌وارد‌کردن در ابزارهای دیگر است.
- `js/database/*.data.js` همان داده در قالب `const ENCYCLOPEDIA = [...]` است تا اپ با یک تگ `<script>` ساده آن را بارگذاری کند. بدین ترتیب برنامه بدون سرور و حتی مستقیم از دیسک (`file://`) اجرا می‌شود؛ در آن حالت `fetch` به فایل JSON محلی را مرورگر مسدود می‌کند، ولی اسکریپت کلاسیک مسدود نمی‌شود.

**قاعده:** منبع حقیقت `js/database/` است و JSON از روی آن بازتولید می‌شود، نه برعکس. پس از هر ویرایش داده، JSON را دوباره بسازید (دستور بازتولید در `README.md` اصلی، بخش «راهنمای توسعه»).

## شمای دانشنامه (`encyclopedia.json`)

آرایه‌ای از دسته‌ها:

```jsonc
{
  "id": "C1",             // شناسه‌ی دسته
  "icon": "botany",       // کلیدی در js/icons.js
  "title": "گیاه‌شناسی و رشد قهوه",
  "items": [
    {
      "id": 1,             // یکتا در کل برنامه (دستورها و مدخل‌ها)
      "title": "…",
      "kind": "item",      // "item" | "note" | "divider"
      "body": "<ul><li>…</li></ul>",   // HTML ساده: p، ul/li، h4، table، div
      "src": [["عنوان منبع", "https://…"]]   // فهرست منبع‌ها
    }
  ]
}
```

- `kind: "item"` به‌صورت مدخل بازشونده، `note` به‌صورت یادداشت همیشه‌باز و `divider` به‌صورت جداکننده‌ی عنوان‌دار نمایش داده می‌شود.
- فیلد `src` فقط در تنظیمات ← منابع و مراجع دیده می‌شود، نه در متن مدخل.

## شمای دستورها (`recipes.json`)

آرایه‌ای از گروه‌ها با همان شکل بالا، با این تفاوت که هر برگ یک نوشیدنی است:

```jsonc
{
  "id": 24,
  "title": "اسپرسو نرمال (Espresso Normale)",   // نام فارسی و در پرانتز نام انگلیسی
  "kind": "item",
  "description": "…",
  "difficulty": "",               // فیلد اختیاری؛ فعلاً در نمایش استفاده نمی‌شود
  "prepTime": "…", "totalTime": "…",
  "origin": "…", "caffeineLevel": "…",
  "equipment": ["…"],
  "ingredients": [{ "amount": "۷", "unit": "گرم", "name": "قهوه‌ی آسیاب‌شده" }],
  "steps": [{ "label": "…", "text": "…", "meta": "…" }],
  "proTip": "…", "variation": "…", "history": "…",
  "src": [["عنوان منبع", "https://…"]]
}
```

- عنوان فقط نام نوشیدنی است؛ جداکردن بخش فارسی و انگلیسی با الگوی `نام (English)` انجام می‌شود.
- `amount` ممکن است عدد، بازه (مانند «۱۴–۱۸») یا متن باشد. تبدیل به امپریال فقط برای مقدارهای عددی با واحد «گرم» یا «میلی‌لیتر» انجام می‌شود.
- نام فایل عکس هر نوشیدنی `assets/photos/drink-<id>.png` است.

## آیکون‌ها

فیلد `icon` رشته‌ای است که باید در رجیستری `js/icons.js` وجود داشته باشد، مانند `history`، `botany`، `roast`، `chemistry`، `technique`، `equipment`، `additive`، `dessert`، `sensory`، `health`، `economics`، `culture`، `art`، `folklore`، `vocabulary`، `safety`، `future`، `coffee`، `droplet`، `milk`، `sparkle`، `pourover`، `immersion`، `autodrip`، `cold`، `traditional`، `unusual` و `rarebeans`. آیکون‌ها SVG‌اند و رنگشان از `currentColor` می‌آید.

## داده‌ی بیرونی

- **امتیاز کاپینگ.** مدخل «میانگین امتیاز کاپینگ بر پایه‌ی مبدأ و روش فرآوری» در دسته‌ی اقتصاد از پایگاه Coffee Quality Institute تجمیع شده است. نسخه‌ی بازتاب‌یافته‌ی آن در GitHub با نام `jldbc/coffee-quality-database` (حدود ۱٬۳۰۰ رکورد عربیکا) منبع این تجمیع بود. میانگین‌ها بر پایه‌ی `Country.of.Origin` و `Processing.Method` محاسبه و گروه‌هایی با کمتر از ۲۰ نمونه حذف شدند تا یک لات غیرعادی میانگین را منحرف نکند.
- **چرخ طعم.** ابزار چرخ طعم برنامه (`FLAVOR_WHEEL` در `tools.data.js`) طراحی SVG اختصاصی پروژه است و بازتولید هیچ نمودار دارای حق نشر نیست.

## قواعد محتوا

- هر گزاره‌ی واقعی باید منبع بررسی‌شده داشته باشد و منبع آن در `src` بیاید.
- «±» در متن فارسی نوشته نمی‌شود؛ بازه به‌کار برید.
- واحدها فارسی نوشته می‌شوند.
- شناسه‌های منتشرشده را تغییر ندهید، چون علاقه‌مندی‌ها و نام عکس‌ها به آن‌ها وابسته‌اند.
